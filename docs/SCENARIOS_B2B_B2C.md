# Сценарии: B2B сейчас, B2C через парсинг витрин

Сейчас система заточена под **B2B-закупку проекта**: прайс поставщика в Excel → спецификация заказчика → КП → согласование → счёт → склад.

**B2C — другой вход тех же сущностей.** Витрина магазина (DNS, Ситилинк, WB, Ozon) = ещё один «поставщик». Парсер кладёт офферы в тот же `PriceListItem`, дальше работает уже существующий генератор КП.

Не смешивать в одном экране: B2B — договор, наценка, NOC; B2C — розничная цена «как на сайте», без круга согласования бухгалтерии.

---

## 1. Что уже есть — это B2B

Актор всегда организация. Источник цен — **файл прайса**, не витрина.

| Код | Сценарий | Кто | Вход | Результат в системе |
|---|---|---|---|---|
| B2B-01 | Поставщик прислал прайс | РП | `.xlsx`/`.xls` (EKF ~20 тыс. строк) | каталог + офферы + архив файла |
| B2B-02 | Заявка по проекту | РП | Excel-перечень (артикул, имя, кол-во) | спецификация, ML-сопоставление |
| B2B-03 | Скидка вендора/бренда | РП | % и срок | применяется в КП автоматически |
| B2B-04 | Три+ КП на тендер | РП | стратегии мин. цена / срок / баланс / ML | сравнение, Excel/PDF |
| B2B-05 | Ручной поставщик в строке | РП | override | КП не ломает стратегию |
| B2B-06 | Наценка и маржа | РП → КБ | markup % | sell price, margin |
| B2B-07 | Согласовать / вернуть | КБ | да/нет + комментарий | статус, resubmit |
| B2B-08 | Счёт NOC | РП + бухгалтерия | договор, файлы, стадии оплаты | снимок позиций |
| B2B-09 | Резерв и заказ | РП | выбранная стратегия | `StockQuantity` уменьшается |
| B2B-10 | Приёмка | склад | факт по строкам | WMS/1С-шлюз, счёт доезжает до «Отражено в 1С» |

Типовые **предметные** заявки B2B (то, чем кормить демо):

| Сценарий | Что в перечне | Зачем на защите |
|---|---|---|
| ЦОД / серверная | серверы, СХД, коммутаторы, ИБП | ядро каталога-сидера, дорогие позиции, разные сроки |
| Офисная партия | ноутбуки, мониторы, МФУ, док-станции | массовые qty, скидка вендора видна в КП |
| СКС / электрика | прайс EKF | «настоящий Excel на 20 тысяч строк» |
| Кривой перечень | опечатки, без артикула, нет в каталоге | экран ML-сопоставления, аналоги |
| Смешанный | 80% матчится, 20% «не найдено» | КП строится по найденным, дыры видны |

## 2. B2C — парсим витрины, не Excel поставщика

Актор — покупатель или менеджер, который сравнивает **розницу**. Поставщик в модели = магазин. Прайс не присылают, его снимают с сайта.

Один технический шов: `Vendor` = «Ситилинк» / «DNS» / «Wildberries», парсер пишет `PriceListItem` (цена, наличие, срок как «самовывоз 0 / доставка N дней»). Генератор КП не переписывается.

### Сценарии B2C

| Код | Сценарий | Сайт-источник | Как парсить | Куда в систему |
|---|---|---|---|---|
| B2C-01 | Корзина «собрать ПК/офис» | DNS, Ситилинк | поиск по модели → карточка: цена, наличие | офферы нескольких магазинов на одну позицию |
| B2C-02 | Смартфон/ноутбук «где дешевле сегодня» | WB, Ozon, Я.Маркет | поиск по запросу, топ-N карточек | сравнение как MinCost-КП |
| B2C-03 | Мониторинг падения цены | любой из витрин | крон раз в N часов, писать `PriceHistoryEntry` | график истории, уже есть сущность |
| B2C-04 | Аналог, если модели нет | WB/Ozon | запрос по имени, ML уже умеет fuzzy | Kind=Analog на розничных карточках |
| B2C-05 | Наличие в городе | DNS, Ситилинк | остаток/самовывоз с карточки | `StockQuantity` |
| B2C-06 | «Не покупай у серого» | WB карточка продавца | юрлицо/рейтинг как метаданные оффера | фильтр в КП: только магазины с ИНН |
| B2C-07 | Комплект периферии | Ситилинк категория | обход категории, не поиск | прайс «как у розницы», без файла |
| B2C-08 | Сверка B2B-прайса с полкой | DNS vs Excel вендора | тот же SKU, два `Vendor` | стратегия ML-актуальность: свежая витрина бьёт тухлый прайс |

Что **не** тащить в B2C из текущего B2B: круг КБ, счёт NOC, приёмка склада, резерв на складе поставщика. Для B2C хватает: спецификация (список желаемого) → офферы с витрин → одно сравнительное КП.

## 3. Откуда снимать (честно по сложности)

| Источник | Тип | Сложность | Заметка |
|---|---|---|---|
| Wildberries `search.wb.ru` | внутренний JSON витрины | низкая | поиск без ключа; цена в копейках (`salePriceU / 100`) |
| Ozon | HTML/JSON, часто антибот | средняя | с домашнего IP иногда пусто, нужен браузер |
| Яндекс Маркет | несколько продавцов на карточке | средняя | сразу несколько офферов на один товар — идеально под КП |
| DNS, Ситилинк | витрина за Qrator | высокая | анонимный HTTP часто режется; для курсача — Playwright по карточке |
| EKF / ЭТМ | B2B-кабинет или файл | уже сделано | это **не** B2C, это текущий импорт Excel |

Для защиты B2C достаточно **одного** живого источника (WB поиск) + **одного** браузерного (Ситилинк по URL карточки). Остальные — адаптеры за тем же интерфейсом, что `IPriceListImporter`.

Контракт адаптера (чтобы не плодить зоопарк):

```
IRetailCatalogClient.SearchAsync(query) → { sku, name, brand, price, inStock, url, shop }
```

`shop` мапится в `Vendor`. Дальше `QuoteGenerator` как есть.

## 4. Демо-перечни электроники (вставить в Excel: Артикул | Наименование | Кол-во)

Импортёр спецификации читает колонки A/B/C, первая строка — заголовок.

### A. B2B — серверная / ЦОД (имена как в сидере, ML должен цепляться даже без артикула)

```
Артикул	Наименование	Количество
		Сервер HPE ProLiant DL380 Gen11	4
		Сервер Dell PowerEdge R760	2
		Коммутатор Cisco Catalyst 9300-48P	6
		Коммутатор Cisco Catalyst 9200L-24P	4
		СХД Dell PowerVault ME5024	1
		ИБП APC Smart-UPS SRT 5000 ВА	2
		Оптический трансивер Huawei SFP+ 10G	24
UNKNOWN-1	Стойка 42U с PDU	2
```

Последняя строка специально «не найдено».

### B. B2B — офис, кривые имена (проверка ML)

```
Артикул	Наименование	Количество
		ноутбук dell latitude 5440	25
		thinkPad t14 gen 4	15
		монитор dell 27 4k ultrasharp	25
		мфу hp laserjet pro m428	3
		док станция thinkpad usb-c	20
		ибп apc smart ups 1500	4
```

Опечатки и другой порядок слов — сценарий fuzzy/TF-IDF.

### C. B2C — розничная электроника (парсить витрины, не прайс завода)

```
Артикул	Наименование	Количество
		Смартфон Apple iPhone 16 128GB	2
		Ноутбук ASUS VivoBook 15	1
		Наушники Sony WH-1000XM5	1
		Видеокарта NVIDIA GeForce RTX 4070	1
		SSD Samsung 990 PRO 2TB	2
		Монитор Xiaomi 27 165Hz	1
```

Артикулов нет: B2C почти всегда идёт **по наименованию**. Парсер ищет запрос на WB/DNS, пишет 2–3 оффера разных магазинов, КП «мин. цена» = где купить дешевле сегодня.

### D. Гибрид (самый полезный на защите)

Одна спецификация офиса. Часть позиций закрыта B2B-прайсом (Lenovo/Dell из Excel), ноутбуки и наушники добираются парсером Ситилинка. В сравнении КП видно: корпоративный вендор vs полка магазина.

## 5. Что не делать

- Не писать универсальный «парсер всего интернета». Один интерфейс, 2 адаптера.
- Не ломать B2B-маршрут согласованием для розничной корзины.
- Не обещать DNS без браузера: антибот реальный, для курсача хватит WB JSON + одна карточка Playwright.
- Парсить только публичную витрину (цены, наличие, название). Личные кабинеты и обход капчи «впрок» — не для этой работы.

## 5.1 Электронный каталог (сделано)

B2B-витрина поверх тех же прайсов, без парсинга магазинов.

| Что | Где |
|---|---|
| Поиск, категории, бренд, поставщик, «в наличии» | `/ecatalog`, query в URL |
| Карточка: офферы, аналоги, история цены | `/ecatalog/{id}`, `GET /api/catalog/{id}` |
| Сравнение до 4 позиций | `/ecatalog/compare?ids=` |
| Подборка → спецификация или CSV | localStorage `ecatalog-cart-v1` |
| Избранное | звезда на карточке |

Дальше обычный B2B-маршрут: спецификация → ML-сопоставление → КП.

## 6. Связь с текущим кодом

| Уже есть | Переиспользуем в B2C |
|---|---|
| `Vendor` + `PriceListItem` | магазин = вендор, карточка = оффер |
| `PriceHistoryEntry` | мониторинг цены с витрины |
| `IRelevanceMatcher` | сопоставить «iphone 16 128» с тем, что вернул поиск |
| `QuoteGenerator` MinCost / MlRelevance | «где дешевле» и «свежая цена + наличие» |
| импорт Excel | остаётся B2B-путём, парсер — второй `IPriceListImporter` |

Сделано: `POST /api/retail/search` + `/retail`. Живой контур — сервис
`ProcurementSystem.Services.Retail` (`:5176`, схема `retail`, шлюз `/api/retail/{**}`).
Съём витрин пишет `RetailShops` в свою схему; импорт офферов идёт в Catalog по HTTP
(`Neighbors:Catalog:BaseUrl`), без копии номенклатуры. Контроллер монолита сохранён.

1. **Wildberries** — JSON `search.wb.ru` (цена в копейках).
2. **Поиск магазинов** — DuckDuckGo HTML «{запрос} купить», заход на найденные URL.
3. **Универсальный съём** — JSON-LD `Product` / OpenGraph, без парсера на каждый сайт.
4. **Известные витрины** — Ситилинк, DNS, Маркет, Регард… Часто 403 без браузера; хост всё равно запоминается.
5. **Импорт** — магазин = `Vendor`, карточка = `Product`, цена = `PriceListItem.SourceUrl`.

Капчу, логин и Qrator не обходим. Вставьте URL карточки, если выдача пустая.
