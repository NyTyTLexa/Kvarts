# Пояснительная записка

Сборка: `python docs/zapiska/build_docx.py` → `docs/zapiska/Пояснительная_записка.docx`.

Структура — по методичке кафедры ИИТ ЧелГУ (дисциплина «Проектирование и разработка распределённых программных систем», заочная форма): титул, задание, содержание, разделы 1–6, список литературы.

## Исходники

Markdown в `src/`:

| Файл | Раздел |
|---|---|
| `01_task.md` | задание на курсовую работу |
| `02_s1_business.md` | 1 Бизнес-анализ |
| `03_s2_analogs.md` | 2 Анализ существующих решений |
| `04_s3_concept.md` | 3 Концепция решения |
| `05_s4_design.md` | 4 Проектирование |
| `06_s5_impl.md` | 5 Реализация |
| `07_s6_testing.md` | 6 Функциональное тестирование |
| `08_references.md` | список литературы |

Содержание глав перенесено из прежней записки (`введение` / три главы / `заключение` / приложения) и из `docs/ТЗ_plain.txt`, `docs/ARCHITECTURE.md`, `docs/DATA_MODEL.md`, `docs/TZ_COVERAGE.md`, `docs/ML_MATCHING.md`, `tests/e2e/e2e_results_2026-09-12.txt`.

## Рисунки

Вставка:

```markdown
![Рисунок N — Название](assets/ris-NN-xxx.png)
```

Сборщик ставит изображение по центру (не шире 160 мм) и подпись «Рисунок N — Название» под ним. Подпись таблицы — строка `Таблица N — …` **над** таблицей.

PNG в `assets/`. Новые схемы (AS IS, Impact Mapping, контекст, прецеденты, CJM, USM, компоненты, диаграммы анкеты) рендерятся `python docs/zapiska/render_figures.py` (HTML + Playwright, графики Pillow). Исходники HTML — `diagrams/`.

## Что заполнить руками

- ФИО студента, номер группы, направление подготовки, подпись и дата на титуле.
- ФИО, должность, степень, звание научного руководителя, подпись и дата.
- После открытия в Word обновить оглавление (F9) и поля номеров страниц.
- При необходимости — наименование предприятия заказчика, если его согласуют отдельно (в ТЗ стоит пометка о согласовании названия системы).
